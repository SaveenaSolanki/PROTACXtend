## 1. Executive Summary

PROTACXtend is **not a mock**. It is a large, genuinely functional scientific
software platform (465 Python modules in the `protacxtend` package alone, ~91k
LOC) with a working deterministic PROTAC-design pipeline, real cheminformatics,
real docking/MD backends, real literature/database retrieval, a real run-provenance
record, and — unusually — an **already-measured external validation layer**
(e.g. AutoDock Vina redocking median RMSD 2.356 Å on 40 experimental complexes;
pocket recovery and PPI docking with an honest negative result; MM/GBSA explicitly
`NOT_VALIDATED`).

It is, however, **not yet the domain-specialized autonomous therapeutic-discovery
agent described in the target specification**, and it is **not benchmark-ready**.
The gaps are specific and verifiable:

1. **The natural-language front door is broken.** `SupervisorAgent` →
   `ProtacDesignToolbox.parse_user_request` (`protacxtend/tools/protac_toolbox.py:275`)
   mis-parses targets. Measured live:
   `"Design PROTACs to degrade BRD4 using VHL"` → **target = `DEGRADE`**;
   `"Can BRD4 be therapeutically degraded in TNBC?"` → **target = `CAN`**.
   An end-to-end run confirmed the flagship target became `DEGRADE`
   (UniProt `O66164`, tractability `0.0`) while still emitting 117 ranked
   candidates. This alone invalidates every target-conditioned result.
2. **The "500-task benchmark" does not exist as a shippable instrument.**
   Three non-interoperable artifacts exist: a 48-case governed set where
   **all 48 `expected_answer` fields are `null`**; a 600-task `eval500` set
   that is **template-generated** (one template per category × 24 targets ×
   18 E3s × 8 linkers) with no grader implementation; and a well-designed
   `TPD-HEADTOHEAD` 500-task allocation where **0 of 500 tasks are scorable**
   (`ground_truth_status = REQUIRES_AUTHORING` for all 500).
3. **The agent is single-pass, not agentic in the planning sense.**
   `DesignPlannerAgent` emits a *static* 19-tool list
   (`protacxtend/agents/design_planner_agent.py`), and
   `DecisionMakingAgent` always returns `run_deterministic_design_workflow`
   (`protacxtend/agentic/decision_making.py`). There is no dynamic tool
   selection, no decomposition loop, no evidence-conflict resolution, no
   self-correction beyond a 1-retry policy on five named nodes.
4. **Tool execution is real but defaults to fixture inputs.** Of 34 agent
   tools, 28 returned `ok` and 6 `partial` in a live sweep — but
   `predict_degradation` defaults to `smiles="CCO"` (ethanol),
   `score_lysine_ubiquitination`/`predict_cooperativity` default to a
   *synthetic* pose (`outputs/stepwise_module_smoke/synthetic_ternary_pose.pdb`).
   Execution success is therefore not scientific evidence.
5. **Large parts of the shipped capability surface is not executable.**
   The repository's own audit registry counts **367 resources**, of which
   **1 is `scientifically-validated`**, 5 `internally-benchmarked`,
   **115 `registered_but_not_executable`** toolkit tools, and
   **49 `registered_but_unavailable`** databases.
6. **No controlled head-to-head has ever run.** `benchmark_results/` contains
   only 4 tasks × 3–4 systems of *capture* smoke tests; no ground-truth score
   exists for any system (`benchmark/scoring/` is empty; no scored aggregate
   anywhere).
7. **Security:** three unquoted `shell=True` subprocess sites and five
   `pickle.load` sites. No remote code execution was attempted; these are
   static findings (Section 23).
8. **Testing is substantial but cannot gate releases:** 954 tests collected,
   `tests/` = 184/186 pass (2 fail), `protacxtend/modules` = 126/126 pass,
   `protacxtend/tests` = 2 failures + several files exceeding 120 s, and the
   **full suite did not complete in 30 minutes** (killed at 54 %).

**Bottom line.** PROTACXtend today is a strong *toolkit* with a credible
scientific-validation spine, wrapped in an under-developed *agent* and an
unfinished *benchmark*. The next version must (a) fix the scientific front door,
(b) build the typed evidence/decision layers, (c) author a real benchmark with
independently verified ground truth, and (d) build the temporal + provenance
machinery — in that order.

## 3. Current Architecture

Two parallel agent stacks exist and are only loosely reconciled:

**A. The deterministic scientific workflow** (`protacxtend/agents/graph.py`).
`LocalSynGlueWorkflowGraph` walks **31 nodes** in a fixed order:
`Supervisor → DesignPlanner → ControlledSearch → Safety → TargetResolver →
BinderRetrieval → Warhead → E3 → ExitVector → Linker → Construction →
StereoEnumeration → Validation → CellContext → ADMET → Novelty → ApplicabilityDomain →
CheapFilter → Degradation → InitialRanking → Diversity → Reflection → Evolution →
ExpensiveSelection → Ternary → Cooperativity → HookEffect → FinalRanking →
ActiveLearning → Report → Memory`. LangGraph is used when importable, otherwise the
local state machine. Terminal gates can stop early (`graph.py:_should_stop`).
The graph is a **pipeline, not a graph**: every edge is `node → next node`.

**B. The seven-layer agentic wrapper** (`protacxtend/agentic/`):
`Perception → Reasoning → GoalSetting → DecisionMaking → Execution → ScientificCritic
→ Learning`, coordinated by `OrchestratorAgent` (`agentic/orchestration.py`).
The decision layer always selects **one** action
(`run_deterministic_design_workflow`), which is executed once, then critiqued and
persisted. This is the layer the README markets as "agentic"; it is a
deterministic single-shot wrapper around stack A, with rule-based risk flags.

**C. Companion surfaces:** `protacxtend/cli.py` (1,721 lines, 34 subcommands),
`protacxtend/backend/api_routes.py` (11 `@app` routes), `protacxtend/app/streamlit_app.py`
(2,315 lines), a Node/TypeScript TUI (`tui/`, 23 skills), and a static website
(`website/`) with a `SCIENTIFIC_CLAIM_AUDIT.md` that is unusually honest.

**D. Two further scaffolding generations** that are *not* wired to the runtime:
`sota/eval/` (mock 500/600-task generators) and `tpdeval/` (the correct 16-domain /
L1–L7 / 300-150-50 design, but empty of tasks).

**Storage reality:** `protacxtend/state/store.py` writes JSON files under
`~/.protacxtend` (projects/sessions/runs); `protacxtend/memory/*` uses SQLite +
BM25; LangGraph checkpoints can use Postgres/SQLite (`agents/checkpointer.py`).
There is **no graph database** and **no vector DB** in the runtime path
(`memory/vector_store.py` falls back to `bm25_text_fallback`).

## 4. Current Agent Execution Flow (traced)

```
USER QUESTION
   │  protacxtend/cli.py or backend/api_routes.py or tui_bridge/server.py
   ▼
SupervisorAgent.run
   │  ProtacDesignToolbox.parse_user_request()   ← BROKEN target parser
   ▼
PerceptionAgent.run                              (agentic layer, additive)
   │  parse again, detect tools/models/memory, risk flags
   ▼
ReasoningAgent.run / GoalSettingAgent.run
   │  rule-based risk interpretation → typed DesignGoal
   ▼
DecisionMakingAgent.choose_next_action
   │  if target missing → ask_user_for_clarification (returns early)
   │  else ALWAYS "run_deterministic_design_workflow"
   ▼
ExecutionAgent.run  → AgenticToolRegistry → backend.main.run_workflow_from_request
   ▼
LocalSynGlueWorkflowGraph.run  (31 nodes, 1 retry max on 5 nodes)
   ▼
ScientificCriticAgent.review     (rule checks, "pass_with_warnings")
   ▼
LearningAgent.store_from_workflow → JSONL memory
   ▼
Metrics + ReportAgent → markdown + CSV + JSON; RunRecord → outputs/runs/<id>/
```

**Measured execution:** the live command
`python -m protacxtend.cli design "Design PROTACs to degrade BRD4 using VHL in triple-negative breast cancer"`
completed with exit 0 in ~a few minutes and produced a 17,689-char report,
180 assembled candidates, 117 valid, 50 finalists, ranked candidates, and a
`Predictions are computational` guardrail section. But the target was
`DEGRADE`, binders = 0, and the warheads were explicitly labelled
`BRD4_demo_quinazoline_like` / `GSPT1_demo_glue_like` ("Included demo warheads
for demonstration"). The report itself states
`Predicted DC50 14.4 nM` with `Degradation confidence 0.25` and
`Applicability domain 0.2614`.

**Stage-by-stage verdict**

| Stage | Exists? | Code path | Strength | Weakness / failure mode |

**Existing benchmark artifacts, verified**

- `benchmark/cases/*.json` — 48 real cases + template. **All 49 `expected_answer`
  values are `null`.** Two tasks (`DISCOVER-01`, `KNOW-08`) reference input CSVs
  that do not exist. Ground truth is 20 `design_rubric` + 9 `mechanistic_rubric`
  + 10 `categorical` + 5 `exact` + 4 `ranked` — i.e. the majority is expert-rubric,
  and no expert has ever scored them (`benchmark/scoring/` empty).
- `benchmark/ERRATUM_v1.0.1.md` records that `KNOW-01` originally froze the

## 18. Multi-Agent Blueprint

Full proposed roster with state/tools/decision ownership:
`audit_nextgen/csv/multi_agent_blueprint.csv`.

**Recommendation: hierarchical multi-agent, but only where independent state,
tools, or reasoning justify it.** Concretely, promote four agents that already

`ABSTAIN` with a user-facing uncertainty statement.

## 19. Evidence Engine Blueprint

Today `protacxtend/research/` retrieves text; nothing types it. The vNext
engine must:

1. **Classify** every retrieved item into one of: `genetic`, `omics`,
   `expression`, `dependency`, `biochemical`, `biophysical`, `structural`,
   `cellular`, `animal`, `clinical`, `computational`, `medicinal_chemistry`,
   `PK`, `safety`.
2. **Store** a typed `EvidenceItem`: `source`, `date`, `evidence_type`, `entity`,
   `context`, `direction` (supports/contradicts/neutral), `strength`,
   `experimental_system`, `sample_size`, `limitations`, `claim`, `confidence`,
   `provenance`.
3. **Build the evidence graph** preserving contradictions:
   `TARGET ↔ DISEASE ↔ PATHWAY ↔ WARHEAD ↔ E3 ↔ PROTAC ↔ STRUCTURE ↔ TERNARY ↔
   DEGRADATION ↔ PHENOTYPE ↔ PK ↔ SAFETY ↔ BIOMARKER`. Edges carry
   `direction`, `strength`, `date`, `source`, and are **never collapsed or
   averaged**.
4. **Rank** by evidence tier (measured > curated/reported > computed >
   predicted > inferred > hypothetical), then recency, then source quality.
5. **Bind** every downstream claim to ≥1 evidence item and expose
   `unsupported_claim` events.

Storage: PostgreSQL for items + citations; a vector index for semantic
retrieval; a graph DB **only if** contradiction traversal justifies it
(Section 20).

## 29. Claim Boundaries / Limitations

The repository already does this well in places
(`config/scientific_status.yaml`, `website/SCIENTIFIC_CLAIM_AUDIT.md`,
`validation/claims.py`, and report guardrails). vNext must enforce it
*mechanically*, not just editorially. Required language primitives, attached to
every generated statement:

- `Computationally prioritized` (no experimental claim)
- `Model-supported hypothesis` (model + version + evidence tier)
- `Requires experimental validation`
- `Evidence incomplete` (missing dependency/omics/clinical)
- `Structure-based plausibility only` (surrogate/docking, not affinity)
- `Predicted, not measured` (ML/ADMET)
- `NOT_VALIDATED` (ternary predicted pose, MM/GBSA)
- `No go/no-go possible: insufficient evidence` (support ABSTAIN)

**Hard rules:** execution success ≠ scientific validity; docking score ≠ binding
affinity; predicted degradation ≠ experimental degradation; predicted ADMET ≠
clinical safety; agent recommendation ≠ validated therapy. The `ScientificCritic`
must scan for violations of these strings and downgrade/`REVISE`.

### WHAT PROTACXtend CAN CLAIM TODAY
- A **working local PROTAC design pipeline** that assembles and RDKit-validates

### WHAT PROTACXtend CANNOT CLAIM TODAY
- That it can autonomously convert a biological question into a validated
  therapeutic strategy (target parsing is broken; no typed strategy).
- That it has a 500-task benchmark (0/500 scorable).
- That any system has been scored head-to-head (no scored run exists).
- That it reasons mechanistically (no causal graph, no falsifiable hypotheses).
- That its degradation/ADMET outputs are experimentally validated.
- That it is reproducible for stochastic engines (Vina `deterministic=false`).
- That tools marked `ok` produced scientifically meaningful output (fixture

claimed degradation/ternary/safety statement to dated primary evidence, combined

provably does this. The repository already has the validation spine (`claims.py`,
external docking benchmarks, honest `NOT_VALIDATED` labels) — the work is to
extend that spine from *tools* to *claims*, *decisions*, and *time*.
