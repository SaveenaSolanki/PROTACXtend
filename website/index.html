About PROTACXtend

A transparent, agentic take on the hardest problem in targeted protein degradation: choosing the right linker, geometry and chemistry — and being able to say why.

Abstract

PROTACs (proteolysis-targeting chimeras) degrade disease proteins by recruiting an E3 ubiquitin ligase — yet their design space is astronomically large: warhead × linker × E3 recruiter combinatorics, ternary-complex geometry, hook effect, and degradation efficiency are coupled in ways that defeat one-shot heuristics.

PROTACXtend frames this as an agentic search problem. A supervisor parses a design objective; resolver agents ground it in UniProt / ChEMBL / BindingDB evidence; design agents assemble candidate chimeras across a 73-method chemistry engine; machine-learning agents score DC50, Dmax and ADMET risk; and physics agents simulate ternary complex feasibility. Every step emits an inspectable trace, so the final Pareto-ranked candidates are decisions with provenance — not black-box outputs.

#protac#targeted-protein-degradation #agentic-science#chemprop#rdkit

Why it matters

  • Design space: linker identity and length dominate ternary-complex formation and degradation potency.
  • Failure modes: hook effect, poor cooperativity (α), metabolic instability and off-target toxicity kill candidates late.
  • Reproducibility: most published PROTAC pipelines are black boxes; PROTACXtend records a Feynman-style decision chain for every candidate.

The Feynman contract

Each node reads a shared typed workflow state, performs one falsifiable task, and writes its evidence back — no agent may silently mutate another agent's conclusions.

  • Deterministic state-machine fallback and a compiled LangGraph path share one node registry.
  • Retry policies and escalation gates pause the run when evidence is missing — never fabricate.
  • Every design, prediction and docking call is checkpointed to session memory for /audit.

Getting started

PROTACXtend installs from PyPI, from the official GitHub repository, or runs directly from a repository-local checkout. Python 3.10+ with conda is recommended for RDKit and PyTorch isolation.

Option A — clone & install (recommended)

git clone https://github.com/the-ahuja-lab/PROTACXtend.git
cd PROTACXtend
conda create -n protacxtend python=3.10 -y
conda activate protacxtend
pip install -r requirements.txt
pip install -e .

Option B — PyPI

pip install protacxtend

Verify the environment

protacxtend status

The diagnostic confirms chemistry modules, RDKit sanitization routines, committed ML artifacts (multitask transformer, grover encodings) and agent tool initialization.

Architecture & the Feynman stack

PROTACXtend organizes PROTAC design as an auditable agent graph running over a 73-method master chemistry engine (protac_toolbox.py). The 23-node core design pipeline plus closed-loop refinement nodes form a 31-node orchestration.

Key system components

  1. Supervisor & planning node — natural-language objective parsing and multi-turn policy execution with retry and escalation gates.
  2. Target & warhead resolution — automated UniProt, ChEMBL, PubChem and BindingDB retrieval with pChembl ranking.
  3. Generative linker assembly — rule-based, curated and GRU generative linker attachment scanning across a 73-method engine.
  4. Physics + ML scoring — Chemprop deep-learning ensemble for DC50/Dmax and P4ward SE(3) ternary-complex feasibility.
  5. Reflection & memory — Feynman-style review, active-learning update, session checkpoints and persistent memory stores.

Design philosophy

Inspired by Feynman — make the invisible visible: invisible molecular interactions become composable, inspectable reasoning steps; black-box predictions become step-by-step decision chains; opaque outputs become auditable evidence trails with human escalation gates.

Workflows & slash commands

Design, prediction, docking and audit workflows execute from the CLI, the Python API or the REST backend.

End-to-end design run

protacxtend design --target "BRD4" --e3 "CRBN" --warhead "pomalidomide" \
  --num-candidates 16 --output ./results/brd4_run.json

Inside: UniProt/ChEMBL lookup → binder retrieval → exit-vector detection → linker generation → construction → stereoisomer enumeration → validation → ADMET + novelty + applicability domain → degradation ML → initial ranking → diversity clustering → reflection → final Pareto frontier.

API reference

PROTACXtend exposes the synglue_agent Python package, a FastAPI REST backend and a CLI.

Python — workflow entrypoint

from synglue_agent.agents.graph import run_syn_glue_workflow

state = run_syn_glue_workflow(
    request="Design 10 CRBN PROTAC candidates for HMGB2 with low hERG risk",
    config={"persistent": True, "max_iterations": 3})

candidates = state["final_candidates"]
report     = state["report_markdown"]

Python — chemistry engine

from synglue_agent.tools.protac_toolbox import PROTACMasterToolbox

tb = PROTACMasterToolbox()
vectors   = tb.detect_exit_vectors(warhead_smiles="...")
protac_sm = tb.assemble_protac(warhead_smiles="...",
                               linker_smiles="...",
                               e3_smiles="...")
